## Rule details

### AGT001 - Agent tool parameter reaches command execution

*Version 1.0.0 | pack `agents` | category `agents`*

A parameter of a function registered as an agent tool (``@tool``, ``@function_tool``, ``Tool(func=...)``, ``tools=[...]``) flows into shell, code, SQL, filesystem, network or deserialization calls without a recognised validation step. Tool arguments are chosen by the model, which can be steered by prompt injection.

- **Confidence:** High for a direct path from a tool parameter to the sink; medium when a validation-looking check references the parameter.
- **Impact:** An attacker who influences the agent's context can execute commands or queries with the agent's privileges.
- **Remediation:** Constrain tool inputs to typed, enumerated values; implement specific operations instead of generic command runners; run unavoidable execution in a sandbox with least privilege and require human approval for high-impact actions.
- **OWASP:** OWASP Top 10 for LLM Applications 2025 LLM06
- **References:**
  - https://genai.owasp.org/llmrisk/llm062025-excessive-agency/
  - https://cwe.mitre.org/data/definitions/78.html

### AGT002 - High-impact tool lacks a recognised approval boundary

*Version 1.0.0 | pack `agents` | category `agents`*

A tool exposed to an agent performs a high-impact action (command execution, SQL, file or network side effects, or a destructive operation suggested by its name), and neither the tool body, its decorators, nor the module show a recognised authorization or human-approval mechanism. This is a heuristic: a custom authorization helper may not be recognised.

- **Confidence:** Medium when the tool body contains a dangerous sink; low when only the tool name or description suggests a destructive action. Always marked review-required.
- **Impact:** The model can trigger irreversible actions without a human or policy check.
- **Remediation:** Gate high-impact tools behind an explicit approval step (framework interrupts, confirmation callbacks, policy checks) and enforce authorization server-side.
- **OWASP:** OWASP Top 10 for LLM Applications 2025 LLM06
- **References:**
  - https://genai.owasp.org/llmrisk/llm062025-excessive-agency/
  - https://cwe.mitre.org/data/definitions/862.html

### AGT003 - Tool exposes unnecessarily broad capabilities

*Version 1.0.0 | pack `agents` | category `agents`*

The agent is given a general-purpose execution tool (shell, Python REPL, raw SQL, unrestricted HTTP or filesystem toolkit), a dangerous-mode flag is enabled, or a tool description advertises arbitrary command/code/file access. Broad tools turn any prompt injection into full control of the host.

- **Confidence:** High for known dangerous tool classes and explicit dangerous-mode flags; medium for description-based matches. Smolagents authorized_imports=['*'] is reported as high.
- **Impact:** The model can perform actions far beyond the task, including data exfiltration and host compromise.
- **Remediation:** Replace generic tools with narrowly scoped functions that accept validated parameters; if execution is necessary, sandbox it, restrict the filesystem root and network, and require approval.
- **OWASP:** OWASP Top 10 for LLM Applications 2025 LLM06
- **References:**
  - https://genai.owasp.org/llmrisk/llm062025-excessive-agency/
  - https://cwe.mitre.org/data/definitions/250.html

### AGT004 - Tool output reaches a privileged path without handling

*Version 1.0.0 | pack `agents` | category `agents`*

The result of a tool call (web search, page fetch, MCP tool, retrieval helper) is passed into command execution, code evaluation, SQL, filesystem, network, dynamic dispatch or another tool without a recognised validation step. Tool results come from third-party systems and can carry injected instructions or payloads.

- **Confidence:** Medium by default because tool receivers are recognised by naming convention; lowered to low when a validation-looking check references the value.
- **Impact:** A malicious web page or tool response can escalate into actions on the host or downstream systems.
- **Remediation:** Validate and type tool results before use; never execute content returned by a tool; pass results to the model as data and let privileged actions go through constrained tools.
- **OWASP:** OWASP Top 10 for LLM Applications 2025 LLM01
- **References:**
  - https://genai.owasp.org/llmrisk/llm012025-prompt-injection/
  - https://cwe.mitre.org/data/definitions/20.html

### CFG001 - Unsafe security configuration

*Version 1.0.0 | pack `code` | category `configuration`*

A security-relevant setting is configured in an unsafe way: debug mode enabled, TLS verification disabled, wildcard CORS with credentials, wildcard allowed hosts, unsafe YAML/pickle loading, privileged containers or write-all workflow permissions.

- **Confidence:** High: each pattern is matched syntactically on a literal value.
- **Impact:** Weakens transport security, exposes debugging interfaces, or widens the attack surface.
- **Remediation:** Use the secure default for the setting in production and load environment-specific values from configuration.
- **OWASP:** OWASP Top 10 2021 A05
- **References:**
  - https://cwe.mitre.org/data/definitions/16.html
  - https://owasp.org/Top10/A05_2021-Security_Misconfiguration/

### DEP001 - Known vulnerable dependency

*Version 1.0.0 | pack `dependencies` | category `dependencies`*

Requires integration: `osv_scanner`.

A dependency version listed in a manifest or lockfile has a published vulnerability in the OSV database. Severity is derived from the advisory's CVSS score when present.

- **Confidence:** High when the advisory carries a severity score; medium when it does not.
- **Impact:** The application inherits the vulnerability; exploitability depends on how the package is used.
- **Remediation:** Upgrade to a fixed version listed in the advisory, or document why the vulnerable code path is unreachable.
- **OWASP:** OWASP Top 10 2021 A06
- **References:**
  - https://osv.dev/
  - https://cwe.mitre.org/data/definitions/1395.html

### LLM001 - LLM output reaches a sensitive operation

*Version 1.0.0 | pack `llm` | category `llm`*

Text or structured output returned by a language model flows into a command, code evaluation, SQL statement, file path, outbound request or dynamic attribute lookup without a recognised validation step. Model output is attacker-influenced whenever any untrusted content (user messages, documents, web pages) reaches the prompt.

- **Confidence:** High for a direct path from a recognised LLM API call to the sink. Medium when a validation-looking check references the value. Dictionary-based dispatch on a fixed tool table is not reported.
- **Impact:** Prompt injection becomes command injection, SQL injection, SSRF or path traversal.
- **Remediation:** Treat model output as untrusted input: parse it into a typed schema, validate each field against an allow-list, and execute privileged actions only through constrained tool wrappers that do not accept free-form commands.
- **OWASP:** OWASP Top 10 for LLM Applications 2025 LLM05
- **References:**
  - https://genai.owasp.org/llmrisk/llm052025-improper-output-handling/
  - https://cwe.mitre.org/data/definitions/74.html

### LLM002 - Untrusted content reaches tool execution

*Version 1.0.0 | pack `llm` | category `llm`*

User-supplied text or content retrieved from a document store is passed directly into a tool invocation (``tool.run(...)``, ``tool.invoke(...)``, ``execute_tool(...)``). Tools typically perform side effects; feeding them unvalidated content lets prompt injection or poisoned documents trigger those side effects.

- **Confidence:** High when the tool receiver is a recognised dangerous tool (shell, Python REPL, SQL, filesystem, HTTP). Medium otherwise because the tool's capabilities are unknown.
- **Impact:** Attacker-controlled content drives privileged tool actions.
- **Remediation:** Route tool calls through the model's structured tool-calling interface with typed, validated arguments; never pass raw user or document text as a tool input.
- **OWASP:** OWASP Top 10 for LLM Applications 2025 LLM01
- **References:**
  - https://genai.owasp.org/llmrisk/llm012025-prompt-injection/
  - https://cwe.mitre.org/data/definitions/20.html

### LLM003 - Secret value embedded in a prompt

*Version 1.1.0 | pack `llm` | category `llm`*

A credential (from the environment, a secrets manager, or a variable whose name indicates a secret) is interpolated into prompt text, a message object, or passed as prompt input to a model API. Prompts are transmitted to the provider, retained in traces, and can be exfiltrated through prompt injection.

- **Confidence:** High when the value comes from an explicit secret source; medium when only the variable name indicates a secret. Passing an api_key= keyword to a client constructor is not reported.
- **Impact:** Credentials leak to the model provider, observability tooling and any user who can elicit the system prompt.
- **Remediation:** Keep secrets out of prompts. Give tools access to credentials server-side and pass only opaque identifiers through the model.
- **OWASP:** OWASP Top 10 for LLM Applications 2025 LLM02
- **References:**
  - https://genai.owasp.org/llmrisk/llm022025-sensitive-information-disclosure/
  - https://cwe.mitre.org/data/definitions/200.html

### LLM004 - LLM output reaches a web boundary without validation

*Version 1.0.0 | pack `llm` | category `llm`*

Model output is rendered as HTML (render_template_string, Markup, mark_safe, HTMLResponse, unsafe_allow_html) or used as a redirect target. These sinks are framework boundaries where encoding or validation is expected; model output that contains markup or URLs chosen by an attacker leads to XSS or open redirects.

- **Confidence:** High for a direct path into a recognised HTML or redirect sink; medium when an escaping or validation call is referenced. Only reported when framework-specific sinks are present, so plain return values are not flagged.
- **Impact:** Cross-site scripting or open redirect driven by prompt injection.
- **Remediation:** Render model output as text (auto-escaped templates, Markdown with HTML disabled) and validate redirect targets against an allow-list of hosts.
- **OWASP:** OWASP Top 10 for LLM Applications 2025 LLM05
- **References:**
  - https://genai.owasp.org/llmrisk/llm052025-improper-output-handling/
  - https://cwe.mitre.org/data/definitions/79.html
  - https://cwe.mitre.org/data/definitions/601.html

### MCP001 - MCP tool input reaches dangerous execution

*Version 1.0.0 | pack `mcp` | category `mcp`*

An argument of an MCP tool handler (``@mcp.tool()``, ``@server.call_tool()``) flows into shell, code, SQL, filesystem, network or deserialization calls without a recognised validation step. MCP clients forward model-chosen arguments, so any prompt injection in the client reaches the server with the server's privileges. For TypeScript/JavaScript servers a regex heuristic flags exec/spawn/eval inside files that import the MCP SDK.

- **Confidence:** High for a direct Python taint path; medium when a validation-looking check references the value; medium for JavaScript/TypeScript heuristic matches.
- **Impact:** Remote command/code execution on the MCP server host by any connected client.
- **Remediation:** Validate tool arguments with a strict schema and allow-lists, avoid shell interpolation, use argument arrays, and restrict filesystem and network scope.
- **OWASP:** OWASP Top 10 for LLM Applications 2025 LLM06
- **References:**
  - https://modelcontextprotocol.io/specification/2025-06-18/basic/security_best_practices
  - https://cwe.mitre.org/data/definitions/78.html

### MCP002 - Overly broad MCP permissions or unsafe execution configuration

*Version 1.0.0 | pack `mcp` | category `mcp`*

An MCP server exposes a generic command/code execution tool, or an MCP client configuration grants broad trust: shell wrappers as server commands, dangerous flags, filesystem servers rooted at '/' or the home directory, or auto-approval of all/destructive tools.

- **Confidence:** High: matched on literal configuration values or tool names combined with execution sinks.
- **Impact:** Any connected model or compromised client can execute commands or modify arbitrary files without a human check.
- **Remediation:** Expose narrowly scoped tools, restrict filesystem roots to project directories, remove auto-approval for destructive tools, and never wrap servers in a shell with user-controlled arguments.
- **OWASP:** OWASP Top 10 for LLM Applications 2025 LLM06
- **References:**
  - https://modelcontextprotocol.io/specification/2025-06-18/basic/security_best_practices
  - https://cwe.mitre.org/data/definitions/250.html

### MCP003 - Secret exposed in MCP configuration

*Version 1.0.0 | pack `mcp` | category `mcp`*

An MCP server definition contains a literal credential: an environment variable value that looks like a secret, an Authorization header, or a URL with embedded credentials. MCP configuration files are frequently committed, synced between machines and readable by every local process.

- **Confidence:** High when the value matches a known token format or sits in an Authorization header or URL; medium when only the key name indicates a secret. Placeholders and ${VAR} references are ignored.
- **Impact:** Credentials are exposed to anyone with access to the config file or repository.
- **Remediation:** Reference secrets through environment variables or the client's secret store (e.g. ${VAR} / input variables) and rotate the exposed credential.
- **OWASP:** OWASP Top 10 2021 A07
- **References:**
  - https://modelcontextprotocol.io/specification/2025-06-18/basic/security_best_practices
  - https://cwe.mitre.org/data/definitions/798.html

### MCP004 - Potential missing authorization at MCP tool boundary

*Version 1.0.0 | pack `mcp` | category `mcp`*

An MCP tool performs a high-impact action (execution, SQL, filesystem, network or a destructive operation) and neither the tool body nor the server setup shows a recognised authorization mechanism (auth provider, token verifier, per-request principal checks). Over stdio the host process is the trust boundary, so the finding is reported at low severity; over network transports it is reported at medium.

- **Confidence:** Low: authorization helpers are recognised by naming convention only, so a custom mechanism may be missed. Always review-required.
- **Impact:** Any client able to reach the server can invoke sensitive tools as the server's identity.
- **Remediation:** Configure server-level authentication (OAuth/bearer token verification) for network transports and enforce per-tool authorization against the authenticated principal.
- **OWASP:** OWASP Top 10 for LLM Applications 2025 LLM06
- **References:**
  - https://modelcontextprotocol.io/specification/2025-06-18/basic/authorization
  - https://cwe.mitre.org/data/definitions/862.html

### MCP005 - Risky MCP network binding or transport

*Version 1.0.0 | pack `mcp` | category `mcp`*

An MCP server binds a network transport to all interfaces (0.0.0.0 / ::), runs a network transport without recognised authentication, or a client configuration connects to a remote MCP server over cleartext HTTP. Network-exposed MCP servers are reachable by other hosts and browsers (DNS rebinding) unless bound to loopback and authenticated.

- **Confidence:** High for literal 0.0.0.0 bindings and cleartext remote URLs; medium for a network transport without a recognised auth marker (review required).
- **Impact:** Unauthenticated remote invocation of MCP tools; credential interception over cleartext.
- **Remediation:** Bind to 127.0.0.1 unless remote access is required, require authentication on SSE/HTTP transports, validate Origin headers, and use HTTPS for remote servers.
- **OWASP:** OWASP Top 10 for LLM Applications 2025 LLM06
- **References:**
  - https://modelcontextprotocol.io/specification/2025-06-18/basic/transports
  - https://cwe.mitre.org/data/definitions/1327.html

### RAG001 - Tenant filtering not evident in retrieval

*Version 1.0.0 | pack `rag` | category `rag`*

A vector/document retrieval call runs inside a function that has a tenant, user, organization or account identifier in scope, but the call passes no filter, namespace, partition or search_kwargs argument and the identifier is not referenced in the call. Multi-tenant RAG systems must scope retrieval server-side; relying on the model or post-filtering leaks other tenants' documents into the context window.

- **Confidence:** Medium: the identifier in scope is strong evidence of multi-tenancy but the collection itself may already be tenant-scoped. Always review-required.
- **Impact:** Cross-tenant data disclosure through retrieved context.
- **Remediation:** Pass a tenant/user filter (metadata filter, namespace, partition or per-tenant collection) to every retrieval call, derived from the authenticated principal.
- **OWASP:** OWASP Top 10 for LLM Applications 2025 LLM08
- **References:**
  - https://genai.owasp.org/llmrisk/llm082025-vector-and-embedding-weaknesses/
  - https://cwe.mitre.org/data/definitions/285.html

### RAG002 - Authorization applied after retrieval

*Version 1.0.0 | pack `rag` | category `rag`*

Documents are retrieved without a filter and then filtered in application code by tenant, owner or permission (list comprehension or if-statement over the results). Post-filtering wastes the top-k budget, leaks document existence through counts and timing, and silently fails when the filter condition does not match the metadata.

- **Confidence:** Medium: the pattern is syntactic; the store may not support pre-filtering.
- **Impact:** Unauthorized documents are loaded into memory and may leak via errors, logs or incomplete filtering.
- **Remediation:** Push the authorization predicate into the retrieval query (metadata filter, namespace or per-tenant index).
- **OWASP:** OWASP Top 10 for LLM Applications 2025 LLM08
- **References:**
  - https://genai.owasp.org/llmrisk/llm082025-vector-and-embedding-weaknesses/
  - https://cwe.mitre.org/data/definitions/285.html

### RAG003 - Retrieved content reaches a privileged action

*Version 1.0.0 | pack `rag` | category `rag`*

Content returned by a vector store, retriever or search index flows into command execution, code evaluation, SQL, filesystem, network, deserialization, dynamic dispatch or HTML rendering without a recognised trust boundary. Indexed documents are frequently attacker-writable (uploads, web pages, tickets), so they must be treated as untrusted input.

- **Confidence:** High for a direct path; medium when a validation-looking check references the value.
- **Impact:** Indirect prompt injection or poisoned documents escalate to code execution or data access.
- **Remediation:** Treat retrieved text as data only: never execute, query or render it; validate extracted fields against strict schemas.
- **OWASP:** OWASP Top 10 for LLM Applications 2025 LLM08
- **References:**
  - https://genai.owasp.org/llmrisk/llm082025-vector-and-embedding-weaknesses/
  - https://cwe.mitre.org/data/definitions/74.html

### RAG004 - Potential sensitive metadata exposure

*Version 1.0.0 | pack `rag` | category `rag`*

Either documents are ingested into a vector store with metadata keys that denote sensitive personal or secret data (which is then returned with every retrieval), or retrieved documents are returned in an HTTP response or written to logs without evidence of metadata scrubbing.

- **Confidence:** High when a literal metadata key is in the sensitive list; medium for retrieved documents returned from a route handler; low for logging of retrieved documents.
- **Impact:** Personal data or secrets stored alongside embeddings leak to clients, logs or the model context.
- **Remediation:** Store only the metadata needed for filtering and citation; keep sensitive attributes in the system of record and return sanitised document views to clients.
- **OWASP:** OWASP Top 10 for LLM Applications 2025 LLM02
- **References:**
  - https://genai.owasp.org/llmrisk/llm022025-sensitive-information-disclosure/
  - https://cwe.mitre.org/data/definitions/200.html

### SEC001 - Potential hard-coded credential

*Version 1.0.0 | pack `secrets` | category `secrets`*

A string literal that looks like an API key, token, password or private key is embedded in source or configuration. Hard-coded secrets leak through version control, build artifacts and logs, and cannot be rotated without a code change.

- **Confidence:** High when the value matches a known provider token format (e.g. OpenAI, AWS, GitHub) or has high entropy; medium for generic key=value assignments. Placeholders and environment references are ignored.
- **Impact:** Anyone with read access to the repository or artifact can use the credential.
- **Remediation:** Move the secret to an environment variable or a secrets manager, rotate the exposed value, and add the file pattern to your secret-scanning pre-commit hook.
- **OWASP:** OWASP Top 10 2021 A07
- **References:**
  - https://cwe.mitre.org/data/definitions/798.html
  - https://owasp.org/Top10/A07_2021-Identification_and_Authentication_Failures/

### SEC002 - Sensitive value exposed in logs

*Version 1.1.0 | pack `code` | category `code`*

A value read from a secret source (environment variable, secrets manager, or a variable whose name indicates a credential) is passed to a logging or print call. Logs are widely replicated and rarely protected like secrets.

- **Confidence:** High when the value comes from an explicit secret source such as os.environ; medium when only the variable name suggests a secret.
- **Impact:** Credentials may be exposed to anyone with log access, including third-party log platforms.
- **Remediation:** Remove the value from the log call or log a redacted/hashed form; configure a redaction filter.
- **OWASP:** OWASP Top 10 2021 A09
- **References:**
  - https://cwe.mitre.org/data/definitions/532.html

### SEC003 - Untrusted input reaches shell execution

*Version 1.0.0 | pack `code` | category `code`*

User-controlled data (HTTP request data, stdin, CLI input) flows into a subprocess or shell execution call. With shell=True or string commands this allows command injection; with argument lists it can still inject arguments.

- **Confidence:** High for a direct taint path. Medium when a validation-looking check references the value. A shell=True call with a dynamic but untainted command is reported as a low-confidence potential issue.
- **Impact:** Remote command execution on the host running the application.
- **Remediation:** Never pass untrusted input to a shell. Use argument lists without shell=True, validate against a strict allow-list, and prefer library APIs over spawning processes.
- **OWASP:** OWASP Top 10 2021 A03
- **References:**
  - https://cwe.mitre.org/data/definitions/78.html
  - https://owasp.org/Top10/A03_2021-Injection/

### SMG001 - Semgrep rule match

*Version 1.0.0 | pack `code` | category `code`*

Requires integration: `semgrep`.

A locally configured Semgrep rule matched. The upstream check id, message and severity are preserved. AegisAI does not independently verify Semgrep findings.

- **Confidence:** Medium: inherits the upstream rule quality; review each match.
- **Impact:** Depends on the matched rule.
- **Remediation:** Follow the remediation guidance of the matched Semgrep rule.
- **References:**
  - https://semgrep.dev/docs/
